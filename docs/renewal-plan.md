## 3. 플레이 경험

### 화면과 흐름

`타이틀/조작 안내 → 수업 시작 → 반복 플레이 → 결과/재도전`의 네 화면 상태로 충분하다. 화면 배치는 스토리 썸네일과 기존 게임의 관계를 따른다. **셰럼은 왼쪽 아래 전경**, 학생 둘은 **오른쪽 위**에 둔다. 학생 자리에서는 **죠안이 왼쪽, 에르핀이 오른쪽**이다. 셰럼이 화면 **왼쪽**을 보면 학생들에게 등을 돌린 안전 상태, **오른쪽**을 보면 학생들을 감시하는 위험 상태다. 학생과 셰럼 사이의 빈 공간에 새 배경·수업 사물을 배치하되, 캐릭터가 화면에서 가장 먼저 읽혀야 한다. 점수·흥 게이지·빵 아이템은 캐릭터 얼굴을 가리지 않는 상단 가장자리에 둔다. 1판은 종료 조건까지 이어지고, 짧게 여러 번 도전하는 생존 점수전으로 한다. PC 브라우저에서는 스페이스바와 Z를, 모바일 가로 화면에서는 누르고 있는 동안 춤추는 큰 터치 버튼과 빵 버튼을 사용한다. 세로 화면에는 회전 안내를 제공한다. 랭킹, 계정, 스토리 분기, 다수 스테이지는 첫 버전 범위에서 제외한다.

### 규칙 초안

1. **스페이스바 또는 화면의 춤 버튼을 누르는 동안** 에르핀이 춤춘다. 셰럼이 뒤돌아 있을 때만 점수와 흥 게이지가 오른다. 점수는 `안전하게 춤춘 시간 × 점수율`로 계산한다.
2. 셰럼은 `왼쪽 보기(안전) → 오른쪽으로 돌 조짐 → 오른쪽 보기(감시) → 왼쪽으로 복귀` 상태를 반복한다. 조짐에는 몸짓과 효과음을 함께 써서 화면을 보지 못하는 순간에도 반응할 단서를 준다. 화면 좌우를 뒤집어 사용하는 임시 애니메이션보다 각 방향을 읽기 쉬운 별도 그림이 좋다.
3. 주시 상태에서 춤을 계속 추면 들킨다. 돌아보는 순간의 반응 여유는 짧게 주되, 시각 예고가 보인 뒤에는 판정이 일정해야 한다. 여유 시간과 상태 길이는 플레이 테스트에서 조정한다.
4. 춤추지 않을 때 흥 게이지가 줄고, 0이 되면 수업을 버티지 못한 것으로 종료한다. 춤으로 오르는 양과 대기 중 줄어드는 양은 **초당** 수치로 계산한다.
5. **Z 또는 화면의 빵 버튼은 죠안이 건넨 빵을 에르핀이 먹는 행동**이다. 1판에 2회, 흥 게이지를 즉시 일부 회복하고 에르핀의 짧은 빵 먹기 포즈를 재생한다. 감시 중 춤을 허용하거나 무적을 주지는 않는다. 빵은 스토리 연결과 위기 탈출 역할만 맡긴다.
6. 죠안은 초반에 에르핀이 춤추면 놀라서 굳어 있다. 기준 시간(초기안 60초)이 지나면 에르핀이 춤출 때 같이 춤추고, 셰럼이 오른쪽으로 돌기 전에 먼저 멈춘다. 죠안은 입력·점수·게이지·실패 판정의 대상이 아니며 **절대 들키지 않는다**.
7. 결과 화면에는 점수, 버틴 시간, 실패 이유, 최고 점수(로컬 저장), 즉시 재도전 버튼을 보여준다.

초기 튜닝 가설: 셰럼이 판서하는 구간 2~4초, 주시 구간 1.5~3초, 방향 전환 예고 약 0.5초. 이 값은 확정 사양이 아니다. 첫 플레이 30초 안에 규칙을 이해할 수 있고, 첫 실패에서 **왜 졌는지** 알 수 있는지가 수치보다 우선한다.

### 캐릭터 연출

- **에르핀:** 오른쪽 위의 플레이어 캐릭터. 지루함과 난리부르스 춤의 대비가 핵심이다. 큰 팔동작·몸통 회전·치맛자락과 머리카락의 후행 움직임으로 춤을 만든다. 기본 표정은 원본 `erpin_idle.gif`의 흰 눈과 작은 열린 입, Z 사용 시에는 빵을 입에 대고 먹는 포즈, 셰럼에게 들키면 놀라 굳는 포즈로 구분한다.
- **셰럼:** 왼쪽 아래의 선생 캐릭터. 왼쪽 보기와 오른쪽 보기의 얼굴 방향이 즉시 읽혀야 한다. 오른쪽으로 도는 예고는 표정만 바꾸지 말고 몸 각도와 사운드로 나타낸다.
- **죠안:** 에르핀 왼쪽의 자동 반응 캐릭터. 초반에는 에르핀의 춤에 놀라 굳고, 이후에는 함께 과장되게 춤춘다. 셰럼이 돌아보기 전 자동으로 멈춰 늘 안전하다. 빵 아이템 제공 반응도 맡는다.
- **교주:** 화면 밖에서 수업에 참여했다는 정도의 짧은 상황 설명만 사용한다. 플레이 캐릭터를 늘리지 않는다.

## 4. 비주얼·사운드 제작 지침

### 크레파스 느낌의 독자적인 팬아트

- 썸네일처럼 머리가 몸보다 크게 보이는 강한 **chibi·데포르메** 비율을 사용한다. 모든 캐릭터의 다리와 발은 몸 아래에 짧게 붙고 긴 인간형 다리로 보이지 않게 한다. 볼은 얼굴 외곽에서 살짝 튀어나오되, [v2 죠안의 빵 건네기 시안](../assets/concepts/2026-10-22/v2/joanne-bread-offer.png) 정도를 상한 기준으로 삼는다. 큰 분홍 원처럼 볼을 과장하지 않는다.
- 얼굴은 [제공된 셰럼 얼굴 참고](../assets/concepts/2026-10-23/v4/reference-sherum-face.png)의 작은 눈·입, 절제된 홍조, 굵은 크레파스 선을 공통 기준으로 삼는다. 전신 외형은 기존 게임의 [에르핀 GIF](../src/ricktcal_game/resources/animations/erpin_idle.gif), [죠안 GIF](../src/ricktcal_game/resources/animations/joanne_idle_1.gif), [셰럼 GIF](../src/ricktcal_game/resources/animations/sherum_front.gif)를 참고한다. 에르핀의 작은 흰 날개·왕관·금발·붉은 망토, 죠안의 검정/금색 긴 머리 장식·녹색 머리·긴 검정/크림 의상·사슬, 셰럼의 뿔·장미 장식 달린 크림색 모자·남색 머리·두루마리·붉은 리본을 식별 요소로 남긴다. **에르핀의 지팡이는 인게임 그림에서 전부 제거한다.** GIF를 새 배포물에 그대로 사용하지 않는다.
- 에르핀의 **기본 표정은 `erpin_idle.gif`처럼 흰 원형 눈과 작은 열린 입**이다. 춤출 때는 눈을 감을 수 있고, 들켰을 때는 놀란 입과 [눈 참고 이미지](../assets/concepts/2026-10-22/erpin.png)의 분홍빛 홍채·금색 별 동공을 쓴다. 죠안의 기본 눈은 GIF와 같은 붉은색이며, **당황해 굳은 순간에만 흰색 원형 눈**으로 바뀐다. 흰 땀방울도 그 순간의 **죠안에게만** 붙인다. 셰럼은 참고 이미지의 푸른색·호박색 눈을 유지하며, 에르핀과 셰럼에는 땀방울을 넣지 않는다.
- 손가락이 드러나면 손마다 **엄지를 포함해 네 개**만 그린다. 작은 게임 화면에서는 손을 단순한 장갑 형태로 처리해도 된다.
- 외곽선은 굵고 울퉁불퉁한 짙은 남색 또는 갈색 크레파스 선으로 그린다. 내부 채색은 큰 단색 면 위에 약한 종이·크레파스 결만 둔다. 부드러운 유화·반짝이는 금속·복잡한 금장 장식은 피한다. 얼굴·몸·방향을 먼저 읽을 수 있어야 한다.
- 전체 색은 하늘색·잔디색·크림색·짙은 갈색을 기본으로 하고 캐릭터별 식별색만 추가한다. 배경과 사물에도 같은 제한 팔레트와 크레파스 선을 적용한다.
- 스토리 썸네일의 밝은 하늘과 초록 바닥, 갈색 수업 책상을 간략화해 화면 구도를 잡는다. 원본 썸네일을 그대로 붙이거나 따라 그리지 않고, 캐릭터 셋이 먼저 보이는 새 배경을 제작한다.
- 원본 편집 파일(레이어 포함)과 게임용 출력물을 분리 보관한다. 게임용은 투명 PNG 아틀라스와 프레임 정보로 내보내며, 실제 필요한 크기와 프레임 수만 사용한다.

| 우선순위 | 제작물 | 첫 버전 기준 |
| --- | --- | --- |
| 필수 | 에르핀 | 대기, 난리부르스 춤, 빵 먹기, 들킴: 4상태. 춤은 서로 다른 큰 동작 4~6프레임으로 시작. 지팡이 없음 |
| 필수 | 셰럼 | 왼쪽 보기, 오른쪽 회전 예고, 오른쪽 보기, 왼쪽 복귀: 4상태 |
| 필수 | 죠안 | 대기, 놀라 굳음, 안전하게 함께 춤, 빵 제공: 4상태 |
| 필수 | 배경·사물·UI | 썸네일 구도를 따른 간결한 수업 배경, 책상·종이·빵, 타이틀, 버튼, 게이지, 점수, 결과 화면 |
| 필수 | 소리 | 직접 제작하거나 사용 허락을 확인한 짧은 반복 음악 1곡, 방향 전환·춤·빵·실패·UI 효과음 |
| 후순위 | 장식 | 추가 춤, 표정, 배경 낙서 변화, 작은 파티클 |

정지 화면 1장과 캐릭터 세 명의 대표 포즈로 먼저 아트 방향을 검증한다. 이후 필요한 애니메이션만 제작한다. 추출 GIF의 대용량·과도한 프레임 수를 그대로 재현하지 않는다.

첫 콘셉트 시안은 [첫 번째 시안](../assets/concepts/2026-10-22/README.md)에, 썸네일 구도를 반영한 두 번째 시안은 [v2 에셋 목록](../assets/concepts/2026-10-22/v2/README.md)에 둔다. GIF의 전신 외형을 반영한 [v3 시안](../assets/concepts/2026-10-23/v3/README.md)을 거쳐, **현행 캐릭터·배경·사물·UI 기준은 [v4 리터칭 출력물](../assets/concepts/2026-10-23/v4/retouched/README.md)**이다. 셰럼 칠판 보기 포즈의 볼 위치와 죠안의 합류 후 춤 장면이 수정되었다. 포즈 시트를 곧바로 최종 애니메이션 아틀라스로 취급하지 않는다.

## 5. 브라우저 구현과 배포 방향

### 기술 선택

| 선택지 | 장점 | 이번 프로젝트에서의 판단 |
| --- | --- | --- |
| 현 Pygame + Pygbag | Python 규칙 코드 일부를 재사용할 수 있다 | 브라우저용 비동기 게임 루프와 리소스 처리 변경이 필요하다. 기존 코드와 에셋을 전면 리뉴얼하므로 재사용 이점이 작다. [Pygbag 안내](https://pygame-web.github.io/wiki/pygbag/) |
| **TypeScript + Canvas 2D + Vite** | 정적 파일로 빌드되고 브라우저 입력·오디오·화면 크기를 직접 다룰 수 있다 | **권장안.** 1화면 2D 게임에 충분하며 별도 게임 엔진과 서버가 필요 없다. |
| 자체 클라우드 서버 | 추후 계정·온라인 랭킹에 쓸 수 있다 | 첫 버전에는 지속 운영, 비용 관리, 보안 관리에 비해 필요한 서버 기능이 없다. |

- 기존 저장소 안의 `web/`을 새 앱의 루트로 만든다. `src/`의 Pygame 코드는 규칙 참고용으로 두고, 새 웹 앱이 준비된 후 정리한다. UI는 HTML/CSS, 캐릭터와 배경은 Canvas 2D로 그린다.
- 규칙 상태를 `title / playing / result`와 셰럼의 `left_safe / turning_right / right_watching / turning_left`로 단순화한다. 죠안의 `idle / shocked / dancing` 표현 상태는 별도로 둔다. 점수·게이지·감시 타이머는 `requestAnimationFrame`의 경과 시간(`dt`)으로 계산하고, 30fps와 60fps에서 같은 결과가 나와야 한다.
- 논리 화면 크기를 정해 캔버스를 화면에 맞게 확대·축소한다. 게임용 PNG 아틀라스는 브라우저에서 실제 표시할 크기에 맞춘다. 초기 로딩 중 진행 상태와 로딩 실패를 보여준다.
- 키보드와 터치가 같은 게임 명령을 호출한다. Space의 페이지 스크롤을 막고, 키를 뗌·포인터 취소·창 포커스 상실 시 춤 상태를 즉시 해제한다. 탭이 숨겨지면 게임 시간을 일시 정지한다.
- 브라우저 자동 재생 정책에 맞춰 시작 버튼을 누른 뒤 오디오를 재생한다. 소리 켜기/끄기와 볼륨을 제공한다. [MDN Web Audio 안내](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Using_Web_Audio_API)
- 판정을 렌더링과 분리해 방향 전환 직전 입력 해제, 죠안의 합류 시간·자동 정지·실패 판정 제외, 빵 소진, 게이지 0, 재시작, 포커스 상실을 작은 자동 테스트로 검증한다.
- 최고 점수와 볼륨은 `localStorage`에 저장한다. 저장이 차단되거나 비공개 모드라면 그 판의 플레이는 계속되며, 최고 점수만 유지되지 않을 수 있음을 결과 화면에 짧게 알린다. 온라인 랭킹을 원할 때만 서버 저장소를 추가한다. [MDN Web Storage 안내](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)

### 호스팅 권장안

**Cloudflare Pages에 블로그와 별도 프로젝트로 배포**한다. 이 저장소를 연결하고 루트 디렉터리를 `web`, 빌드 명령을 `npm run build`, 출력 디렉터리를 `dist`로 설정한다. 먼저 게임 전용 `*.pages.dev` 주소로 확인하고, 필요할 때 블로그 도메인의 별도 서브도메인을 연결한다. 블로그에는 게임으로 가는 링크만 추가하면 된다. [Pages Git 연동](https://developers.cloudflare.com/pages/get-started/git-integration/), [커스텀 도메인](https://developers.cloudflare.com/pages/configuration/custom-domains/)

Vercel도 정적 배포가 가능하지만 이미 CodeMaru가 올라간 사실만으로 새 게임을 같은 프로젝트에 넣을 이유는 없다. Vercel을 쓴다면 게임용 별도 프로젝트가 맞다. 자체 클라우드의 정적 스토리지+CDN도 가능하지만 첫 버전에서는 운영 구성이 늘어난다. **서버, 데이터베이스, Pages Functions는 초기 범위에 포함하지 않는다.** Cloudflare Pages의 무료 요금제에는 프로젝트·빌드·개별 파일 크기 제한이 있으므로, 실제 배포 전 현재 계정과 빌드 결과물을 확인한다. 특히 Pages의 단일 정적 파일 한도는 25MiB다. [Pages 제한](https://developers.cloudflare.com/pages/platform/limits/)

## 6. 작업 순서와 완료 기준

| 단계 | 예상 노력(1인 기준) | 산출물과 통과 조건 |
| --- | --- | --- |
| 0. 자료·권리·시안 확인 | 1~2일 | 제공 영상으로 수업 장면을 대조한 설정 메모, 캐릭터·배경 레퍼런스 보드, 독자적인 화면 시안 1장 |
| 1. 웹 규칙 프로토타입 | 3~4일 | 임시 도형만으로 PC 키보드·모바일 터치에서 시작→플레이→실패→재도전이 동작. 30/60fps 판정 일치 |
| 2. 아트 제작·적용 | 4~8일 | 세 캐릭터 필수 상태, 배경, UI를 새 원화로 교체. 감시 방향을 한눈에 파악 가능 |
| 3. 사운드·마감 | 2~3일 | 자체 제작 또는 사용 허락 확인한 소리, 볼륨 설정, 결과 화면, 최고 점수 저장 |
| 4. 브라우저 테스트·배포 준비 | 2~3일 | Chrome·Firefox·Safari, 모바일 Safari·Chrome에서 입력·오디오·화면 확인. Pages 별도 프로젝트 설정과 빌드 결과 검증, 출처 목록 정리 |

총 **12~20 작업일**은 1인 제작의 대략적인 계획값이다. 그림의 완성도와 모바일 조작 수정 횟수가 가장 큰 변수다. 아트가 막히지 않게 1단계 프로토타입과 정지 화면 시안을 먼저 맞춘다.

### 출시 전 확인할 경험 기준

- 첫 플레이에서 조작 안내를 읽고 10초 안에 춤을 시작할 수 있다.
- 셰럼의 돌아보기 예고와 실제 감시 상태를 매번 구별할 수 있다.
- 셰럼이 왼쪽을 보면 안전, 오른쪽을 보면 위험이라는 방향 관계가 한눈에 보인다.
- 죠안은 초반에 놀라 굳고 기준 시간 이후 함께 춤추며, 어떤 상황에서도 죠안 때문에 게임 오버가 나지 않는다.
- 실패 이유가 `들킴` 또는 `흥 고갈`로 정확히 표시된다.
- 30fps와 60fps에서 점수·게이지·감시 시간이 실질적으로 같다.
- PC 키보드와 모바일 가로 화면 터치에서 같은 규칙으로 플레이된다. 탭 전환과 포커스 상실 후 춤 입력이 남지 않는다.
- 사용자가 시작하기 전 음악이 재생되지 않고, 시작 후에는 음소거와 볼륨 조절이 동작한다.
- 오래된 GIF, 공식 게임에서 추출한 이미지·음원, 공식 로고가 새 배포물에 없다.
- Pages 미리보기 주소에서 처음 실행부터 재도전까지 파일 누락이나 경로 오류가 없다.

## 7. 팬게임 배포와 에셋 권리

에피드게임즈의 [2차 창작 가이드라인](https://epidgames.oqupie.com/portal/2399)은 무료·비상업적 팬 창작을 안내하면서, 공식 원본의 그대로 사용·복제·단순 수정, 공식 로고 사용, 공식 작품으로 오인될 표현을 제한한다. 제3자 제작 GIF는 원본 IP와 제작자 권리가 함께 얽힐 수 있으므로 새 배포물에서 제외하는 방향이 적절하다. 새 그림과 소리도 제작자·사용 허락·출처를 기록한다. 제목 화면과 README에 `트릭컬 리바이브 비공식 팬게임`을 명확히 표시한다.

가이드라인에서 **팬게임 배포 방식 자체가 명시적으로 확인되는지**는 출시 전에 다시 점검한다. 공개 배포나 수익화 계획이 구체화되면 당시 최신 지침과 필요한 허락 범위를 확인한다. 고전 플래시게임에서는 누르고 멈추는 규칙만 참고하고 원작 화면·음악·효과음·대사를 가져오지 않는다.

## 8. 구현 전 결정할 항목

1. 직접 그린 아트의 목표: 크레파스 질감이 강한 손그림과 간결한 게임용 선 사이에서 정지 화면 시안으로 결정.
2. 공개 주소: 우선 게임 전용 `*.pages.dev`, 추후 블로그 도메인의 게임용 서브도메인 연결 여부.
3. 온라인 랭킹이나 계정 기능을 장래에 넣을지. 첫 버전은 브라우저 안의 개인 최고 점수만 제공한다.
