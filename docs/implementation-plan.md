# 선새임 몰래 춤추기 구현 기록

작성일: 2026-10-23

[리뉴얼 기획안](renewal-plan.md)을 `web/` 디렉터리의 브라우저 게임으로 구현한 결과를 기록한다. 수치와 구조는 `web/src/config.ts`, `web/src/game/sim.ts`, `web/src/render/layout.ts`의 실제 코드를 기준으로 작성했다.

## 1. 개요와 기술 선택

기존 Pygame 프로젝트는 제거하고, 같은 규칙을 TypeScript로 새로 만들었다.

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 언어와 도구 | TypeScript, Vite | 빌드 결과가 정적 파일이므로 어떤 정적 호스팅에도 올릴 수 있다. |
| 렌더링 | Canvas 2D | 1화면 2D 게임에는 충분하며 게임 엔진이 필요하지 않다. 메뉴와 버튼은 HTML/CSS 오버레이로 만들었다. |
| 오디오 | Web Audio API | 외부 음원 없이 코드로 합성하므로 권리 문제와 파일 용량 부담이 없다. |
| 테스트 | Vitest | DOM에 의존하지 않는 순수 시뮬레이션만 검증하므로 Node 환경으로 충분하다. |
| 서버 | 사용하지 않음 | 최고 점수와 볼륨은 `localStorage`에 저장한다. 계정과 랭킹이 없으므로 서버를 운영할 이유가 없다. |

논리 해상도는 1280×720이고, 캔버스는 `devicePixelRatio`를 반영하여 화면에 맞춰 레터박스 방식으로 확대·축소한다. `vite.config.ts`에서 `base: './'`로 지정하여 상대 경로로 빌드한다.

## 3. 게임 규칙과 상태 기계

화면 상태는 `title → playing → result`이고, 플레이 중에는 일시정지 여부를 별도 플래그로 둔다. 시뮬레이션 내부의 모드는 `playing`, `caught`, `over`이다.

### 셰럼 상태 기계

```
left_safe → turning_right → right_watching → turning_left → left_safe
```

| 단계 | 의미 | 지속 시간 | 점수·게이지 증가 | 들킴 판정 |
| --- | --- | --- | --- | --- |
| `left_safe` | 칠판을 보는 안전 구간 | 난이도 범위에서 랜덤 | 있음 | 없음 |
| `turning_right` | 돌아보기 예고(느낌표, 효과음) | 0.5초에서 0.25초로 감소 | 있음 | 없음 |
| `right_watching` | 학생들을 보는 위험 구간 | 난이도 범위에서 랜덤 | 없음 | 진입 후 0.15초 뒤부터 |
| `turning_left` | 칠판으로 복귀 | 0.3초 | 없음 | 없음 |

안전 여부는 `left_safe`와 `turning_right`일 때만 참이다. 랜덤 지속 시간은 단계에 진입할 때 `rng.next()`를 정확히 한 번 호출하여 결정하므로, 프레임 속도가 달라도 같은 시드에서 같은 순서가 나온다.

### 들킴 판정

`right_watching`에 진입한 뒤 유예 시간(`graceDuration`, 0.15초)이 지나고도 춤 입력이 유지되면 즉시 들킨다. 유예 시간 안에 입력을 떼면 들키지 않는다. 들키면 `caughtFreeze`(1.2초) 동안 연출을 보여 주고, 이 시간에는 입력을 무시한 뒤 결과 화면으로 넘어간다.

### 흥 게이지

- 안전 구간에서 춤추면 초당 14씩 오르고, 상한은 100이다.
- 위험 구간(`right_watching`, `turning_left`)에서 춤추는 동안에는 오르지도 줄지도 않는다.
- 춤을 추지 않으면 초당 9씩 줄어든다. 0이 되면 `bored`로 종료한다.
- 게이지가 정확히 0이 되는 시각까지만 시간을 진행하고 종료하므로, 큰 `dt`에서도 종료 시각이 일정하다.

### 빵

`breadPressed`는 키를 누른 프레임에만 참인 에지 입력이다. 빵이 남아 있으면 게이지를 35 회복하고, 에르핀이 0.8초 동안 빵을 먹는 포즈를 취하며, 죠안이 0.8초 동안 빵을 건넨다. 먹는 동안에도 들킴 판정은 그대로 적용되므로 무적이 아니다. 빵이 없으면 `bread_empty` 이벤트만 발생한다.

### 죠안

죠안은 입력, 점수, 종료 조건에 관여하지 않는 표시 전용 상태이다. 따라서 죠안 때문에 게임이 끝나는 경우는 구조적으로 존재하지 않는다.

- 60초 이전: 에르핀이 춤추면 `shocked`가 되고, 멈춘 뒤에도 1.0초 동안 `shocked`를 유지한다.
- 60초 이후: 에르핀이 춤추고 셰럼이 `left_safe`일 때만 `dancing`이다. `turning_right`에 들어가면 즉시 `idle`이 되어 먼저 멈춘다.
- 빵을 건네는 중에는 다른 상태보다 `bread`가 우선한다.

### 콤보

안전하게 연속으로 춤춘 시간(`streak`, 초)에 따라 점수 배율이 `1 + min(streak, 10) × 0.05`로 커지며 최대 1.5배이다. 춤을 멈추면 `streak`가 0이 된다. 점수는 구간 길이에 대한 배율의 적분값으로 계산하므로 프레임 속도에 영향을 받지 않는다.

### 시간 진행 방식

`step(state, input, dt)`는 `dt`를 0.1초로 제한한 뒤, 단계 전환, 유예 시간 경계, 게이지 고갈 시점에서 구간을 잘라 계산한다. 한 번의 `step` 안에서 처리하는 구간은 최대 32개이다. 이렇게 하면 30fps와 60fps에서 점수와 종료 시각이 거의 같다.

## 4. 튜닝 수치와 난이도 곡선

| 항목 | 값 |

| `scoreRate` | 100점/초 |
| `gaugeGainPerSec` / `gaugeDrainPerSec` | 14 / 9 (초당) |
| `gaugeMax` / `gaugeStart` | 100 / 100 |
| `breadCount` / `breadHeal` | 2회 / 35 |
| `eatDuration` / `offeringDuration` | 0.8초 / 0.8초 |
| `warnDurationStart` / `warnDurationEnd` | 0.5초 / 0.25초 (난이도 곡선 참고) |
| `graceDuration` | 0.15초 |
| `turnBackDuration` | 0.3초 |
| `joanneJoinTime` | 60초 |
| `shockedLinger` | 1.0초 |
| `caughtFreeze` | 1.2초 |
| `comboStep` / `comboMaxStreak` | 0.05 / 10 |
| `maxDt` | 0.1초 |

### 난이도 곡선

안전 구간과 감시 구간의 길이 범위, 회전 예고 구간의 길이를 경과 시간(`elapsed`) 기준으로 선형 보간하고, `difficultyRampTime`(120초) 이후에는 끝값으로 고정한다.

| 구간 | 시작(0초) | 끝(120초 이후) |
| --- | --- | --- |
| 안전(`safeDuration`) | 2.5~4.5초 | 1.2~2.5초 |
| 예고(`warnDuration`) | 0.5초 | 0.25초 |
| 감시(`watchDuration`) | 1.5~3.0초 | 2.5~4.0초 |

시간이 지날수록 안전하게 춤출 수 있는 시간은 짧아지고, 셰럼이 학생 쪽으로 도는 예고 시간도 짧아져 더 빨리 돌아본다. 반대로 감시 시간은 길어져 셰럼이 학생 쪽을 더 오래 본다. 단계 길이는 단계에 진입할 때 한 번만 정하므로 fps와 무관하게 결정론적이다. 게이지는 안전 구간의 춤으로만 오르기 때문에 후반으로 갈수록 빵을 아껴 쓰는 판단이 중요해진다.

### 렌더 전용 수치

`RENDER_CONFIG`의 연출 수치는 판정에 영향을 주지 않는다.

| 항목 | 값 |
| --- | --- |
| 춤 틱 fps | 6에서 시작하여 120초에 14까지 선형 증가 (`danceFpsBase` 6, `danceFpsBoost` 8) |
| 각성 시작 | 90초 (`awakenTime`), 흔들림 진폭 1.5배 (`awakenAmpMul`) |
| 바운스 / 좌우 흔들림 진폭 | 10px / 6px |
| 숨쉬기 | scaleY ±1.5%, 주기 1.2초 |
| 들킴 화면 흔들림 | 0.3초, 진폭 12px |

## 5. 에셋 파이프라인

`python3 web/tools/build-assets.py`는 `assets/concepts/2026-10-23/v4/retouched/upscaled-2x/`의 시트를 읽어 `web/public/assets/`에 출력한다. Pillow만 필요하고, 다시 실행하면 같은 결과로 덮어쓴다.

### 시트 분리 방식

시트는 균일한 셀로 이루어진 아틀라스가 아니므로 단순 격자로 자르지 않는다.

1. 시트마다 포즈가 놓인 셀을 원본 픽셀 좌표의 다각형으로 정의한다.
2. 알파 마스크를 4px 블록 단위로 연결 성분 라벨링한다.
3. 한 성분의 85% 이상이 한 셀 안에 있으면 그 성분 전체를 해당 포즈에 배정한다. 날개, 머리카락, 느낌표처럼 셀 밖으로 튀어나온 부분이 자기 포즈를 유지하게 하기 위해서이다.
4. 실제로 두 셀에 걸친 성분만 픽셀 단위로 다각형 경계에서 나눈다. 에르핀의 오른쪽 열에서 춤 포즈의 발과 들킴 포즈의 왕관이 맞닿은 경우가 여기에 해당한다.
5. 알파 경계에 맞게 트리밍하고, 같은 캐릭터의 포즈는 같은 축척으로 줄여 포즈를 바꿔도 크기가 튀지 않게 한다.

### 매니페스트 계약

`manifest.json`은 배경, 스프라이트, 게이지 정보를 담는다. 현재 스프라이트는 21개이고 이미지 전체 용량은 약 8.6MB(8,571,378바이트)이다.

```json
{
  "version": 1,
  "background": { "src": "bg/background.png", "w": 1920, "h": 1080 },
  "sprites": {
    "<key>": { "src": "sprites/<key>.png", "w": 0, "h": 0, "anchorX": 0.5, "anchorY": 1.0 }
  },
  "gauge": { "fillRect": { "x": 0, "y": 0, "w": 0, "h": 0 }, "fillColor": "#87d26b", "trackColor": "#fdf5e0" }
}
```

필수 키는 `erpin_idle`, `erpin_dance`, `erpin_eat`, `erpin_caught`, `joanne_idle`, `joanne_shocked`, `joanne_dance`, `joanne_bread`, `sherum_safe`, `sherum_turning`, `sherum_watching`, `desk_long`, `desk_small`, `bread_plate`, `papers`, `ink`, `ui_gauge_frame`, `ui_bread_icon`, `ui_dance_icon`, `ui_pause_icon`, `ui_label`이다. 앵커는 바닥 중앙(0.5, 1.0)이다. 매니페스트를 불러오지 못할 때를 대비하여 `layout.ts`에 플레이스홀더 크기와 색을 정의해 두었다.

### 게이지 fillRect

원본 게이지 그림에는 초록 채움이 칠해져 있다. 파이프라인은 이 채움을 트랙 색(크림)으로 지운 빈 프레임을 `ui_gauge_frame`으로 출력하고, 내부 트랙 사각형을 프레임 PNG 좌표계의 `gauge.fillRect`(현재 x 90, y 51, w 721, h 57)로 기록한다. 게임은 현재 흥 수치의 비율만큼 이 사각형을 코드로 채운다. 게이지 그림 자체가 게임 상태를 나타내지 않으므로 수치와 표시가 항상 일치한다.

## 6. 렌더링과 레이아웃, 절차적 춤 애니메이션

### 레이아웃

1280×720 논리 좌표 기준 배치는 `layout.ts`에 상수로 있다. 그리는 순서는 배경, 학생 책상 뒤의 죠안과 에르핀, 긴 책상과 빵 접시, 셰럼, 작은 책상과 소품, HUD, 효과 순이다. 작은 책상은 셰럼보다 앞에 그린다.

| 요소 | 위치와 크기 |
| --- | --- |
| 긴 책상 | 좌상단 (560, 470), 폭 760 |
| 죠안 | 발 (760, 520), 높이 330 |
| 에르핀 | 발 (1010, 520), 높이 340 |
| 셰럼 | 발 (250, 790), 높이 520 (화면 아래로 잘림) |
| 작은 책상 | 좌상단 (-40, 600), 폭 520 |
| HUD | 좌상단 빵 아이콘, 중앙 상단 게이지(폭 480), 우상단 점수·시간 라벨과 일시정지 아이콘 |

같은 캐릭터의 포즈는 공통 축척을 쓰므로, 포즈 중 가장 큰 높이를 기준으로 표시 크기를 정한다. 빵 접시는 남은 빵 개수만큼만 표시한다.

### 연출

- 셰럼이 `turning_right`일 때 머리 위에 느낌표 말풍선을 코드로 그리고 몸이 살짝 튄다.
- 들키면 화면이 0.3초 흔들리고 에르핀은 `erpin_caught`, 셰럼은 `sherum_watching` 포즈가 되며 배경이 어두워진다.
- 90초 이후에는 노란 번쩍임과 진폭 증가로 에르핀이 각성한 느낌을 낸다.

### 절차적 춤 애니메이션

정지 포즈 한 장으로 춤을 만들기 위해 4틱 주기로 변형을 반복한다.

| 틱 | 변형 |
| --- | --- |
| 0 | 원본 |
| 1 | 좌우 반전 |
| 2 | scaleY 0.92, 회전 +8° |
| 3 | 좌우 반전, scaleY 1.06, 회전 -8° |

여기에 사인 바운스와 좌우 흔들림을 더한다. 틱 속도는 6fps에서 14fps까지 올라가고, 각성 구간에서는 변형량과 진폭이 1.5배가 된다. 죠안은 같은 함수를 위상 0.5만큼 어긋나게 써서 에르핀과 엇갈리게 움직인다. 대기 상태는 느린 숨쉬기 변형을 쓴다.

## 7. 입력과 브라우저 대응

| 입력 | 동작 |
| --- | --- |
| Space | 누르는 동안 춤. 기본 스크롤은 막는다. |
| Z | 빵 먹기(에지 입력) |
| P, Esc | 일시정지 |
| Enter, Space | 타이틀, 결과, 일시정지 화면에서 확인 |
| 화면의 춤 버튼 | 포인터를 누르는 동안 춤 (우하단) |
| 화면의 빵 버튼 | 빵 먹기 (좌하단) |

- 춤 입력은 `keyup`, 창 `blur`, `visibilitychange`(숨김), 포인터의 `pointerup`, `pointercancel`, `pointerleave`, `lostpointercapture`에서 즉시 해제한다. 터치 중 포인터 캡처를 사용하며, 여러 포인터를 추적하여 모두 떼어졌을 때만 춤을 멈춘다.
- 시작 직후 Space를 계속 누르고 있으면, 키를 뗄 때까지 춤으로 처리하지 않는다.
- 탭이 숨겨지면 게임을 일시정지한다. 화면이 세로로 바뀌어도 일시정지하며, 세로 화면에는 가로 전환 안내를 오버레이로 보여 준다.
- 터치 기기로 판단되면(`pointer: coarse` 또는 터치 입력 감지) 화면 버튼을 표시한다.
- 오디오는 사용자가 시작 버튼을 누른 뒤에 `AudioContext`를 재개한다.
- `localStorage` 접근은 모두 `try/catch`로 감싼다. 저장에 실패하면 결과 화면에 최고 점수가 저장되지 않을 수 있다고 안내한다. 사용하는 키는 `smdc.best`, `smdc.volume`, `smdc.muted`이다.
- 한글 폰트는 Google Fonts의 Jua를 비차단 방식으로 불러오며, 실패해도 시스템 폰트로 동작한다.

## 8. 오디오 합성 구성

외부 음원 파일은 쓰지 않는다. 모든 소리는 마스터 `GainNode` 하나를 거치며, 볼륨과 음소거는 이 노드에서 조절한다.

- **효과음(`sfx.ts`):** `warn`(두 음 상승), `watch`(낮은 쿵), `back`(짧은 틱), `caught`(하강 글리산도와 노이즈), `bored`(느린 하강 세 음), `bread`(통통 두 음), `ui`(클릭), `dance_start`(짧은 업비트). 노이즈는 1초 길이의 화이트 노이즈 버퍼를 공용으로 쓴다.
- **배경음악(`bgm.ts`):** 다장조 C - Am - F - G 코드 진행의 4마디 8비트풍 루프이다. 사각파 멜로디, 삼각파 베이스, 노이즈 하이햇으로 구성되며, 16분음표 격자를 `AudioContext` 시계에 맞춰 25ms 간격으로 호출하는 스케줄러가 0.1초 앞서 예약한다.
- **강도 조절:** `setIntensity(0~1)`에 따라 템포가 128에서 140 BPM까지 오르고, 강도가 0.5 이상이면 하이햇이 켜진다. 변경은 마디 경계에서 적용된다.
- 탭이 숨겨지면 배경음악을 일시정지한다.

## 10. 남은 과제

1. **사운드 청취 튜닝:** 합성 효과음과 배경음악의 음량 균형, 음색, 예고음의 식별성을 실제로 들으며 조정한다.
2. **모바일 실기기 확인:** iOS Safari와 Android Chrome에서 터치 버튼, 가로 전환 안내, 오디오 재생, 포커스 상실 처리를 확인한다.
3. **에셋 용량 최적화:** 현재 약 8.6MB이다. PNG 팔레트화나 WebP 변환을 검토하여 초기 로딩 시간을 줄인다. 파일 하나당 Pages 한도(25MiB)에는 한참 못 미친다.
4. **Cloudflare Pages 배포:** 루트 디렉터리 `web`, 빌드 명령 `npm run build`, 출력 디렉터리 `dist`로 프로젝트를 만들고, 미리보기 주소에서 경로 오류가 없는지 확인한다. 배포 전 에피드게임즈의 2차 창작 가이드라인을 다시 확인한다.
5. **플레이 테스트 기반 수치 조정:** 난이도 곡선, 유예 시간, 빵 회복량, 죠안 합류 시간을 실제 플레이 기록으로 조정한다. 첫 30초 안에 규칙을 이해할 수 있는지와 첫 실패 이유를 알 수 있는지를 우선 기준으로 삼는다.
